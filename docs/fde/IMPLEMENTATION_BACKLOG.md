## Out-of-band work (not one of the 26 numbered features — direct user bug report, addressed immediately per standing priority on explicit user direction)
- **Azure Observability Report: soft-failure masquerading as success, erasing real cached data.** Real root-cause bug found and fixed in `observability_snapshots.py` — `azure_monitor_query.py`'s functions return `{"available": false, ...}` on a Log Analytics failure WITHOUT raising, so `run_refresh()`'s merge logic was treating that as a genuine `"success"` and overwriting real prior data, with the `last_known_good` fallback never engaging (it only checked for actual exceptions). Fixed via a new `_is_soft_unavailable()` check. 11 new tests (`tests/test_observability_snapshots.py`), live-verified against the real host (confirmed `status` correctly flips from `"success"` to `"failed"` with the fallback message after restarting with the fix). See IMPLEMENTATION_LOG.md.
